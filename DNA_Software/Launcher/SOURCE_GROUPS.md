# Provider/version source groups

In a tool choose **Best choice**, one compatible profile file, manual files, or **Select multiple providers / datasets**. Dataset groups retain provider, version, build and import date. You can inspect their members and select all compatible sources. Groups with no direct compatible source are unavailable; use batch preparation/conversion first. Raw consumer chip data can contribute health-relevant genotypes and ancestry markers without being a full genome.

For a single-source tool, explicit group selection creates one child job per distinct compatible content, with exact cached runs reused. Paired FASTQ jobs retain explicit R1/R2 roles. Comparison/phasing tools that need distinct biological roles retain their explicit input controls; provider checkboxes do not invent pairings. Missing references or programs remain pending while other applicable jobs continue. The final source-cited HTML/JSON/PDF overview is stored alongside the source reports and indexed for local AI retrieval.

Best choice is **tool specific**. For reads and alignments it prefers source-matched completed local QC jobs. Read Q30 and alignment mapping fraction are recorded separately; neither is a universal quality or completeness certificate. BAM indexes created by QC and original CRAM reference paths remain linked to their exact jobs. BestDataset can publish QC-supported read/alignment assets without a SNP consensus, using hard links or small reference files instead of copying large files. A raw-only bundle does not manufacture variants.

Converted chip VCFs preserve their parent SHA-256 in per-file metadata. A parent and converted representation do not become two independent measurements. Source IDs, all identical aliases, versions, reference builds and per-SNP primary/supporting provenance survive processing. Two corroborating measured consumer sources may support a research SNP consensus; correlated re-exports can still share errors. This is explicitly not a clinical verification or an independence proof.

Final ancestry weighting requires matching canonical population IDs, panel, panel version, calibration, method version, registered source roots and documented relevant-marker/model weights. Incompatible provider percentages remain separate. Weighted values are exploratory technical summaries, not calibrated ethnicity probabilities. Health conditions, drug advice, PDF claims and incomparable risk models are never averaged into a diagnosis. Original provider PDFs, self-report and local results remain separate evidence classes.

Typed control: `sources.groups`, `sources.preview`, `sources.run`, `sources.cancel`, `workflow.best_dataset`, `workflow.research_synthesis`; shared by GUI, CLI and MCP. No automatic uploads or API requests.
